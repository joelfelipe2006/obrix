## Descrição

Troca o banco de produção de MySQL para PostgreSQL: dependências e driver no `pom.xml`, `docker-compose.yml`, perfis `dev`, `prod` e de teste, e o esquema `V1__schema.sql` ajustado ao PostgreSQL. A documentação passa a citar PostgreSQL.

## Justificativa

Exigência do professor: o projeto deve usar PostgreSQL.

## Itens de configuração afetados

- IC-01 Build e dependências (`pom.xml`)
- IC-02 Configuração da aplicação
- IC-03 Migrations do banco (`V1__schema.sql`)
- IC-04 Banco local de produção (`docker-compose.yml`)
- IC-15 Testes do back-end (`application-test.yml`)
- IC-17 README
- IC-18 Contexto técnico

## Análise de impacto

- **Módulos:** Persistência inteira (todas as tabelas) e a configuração dos perfis.
- **Riscos:** Altos: o esquema inicial `V1__schema.sql` foi editado, o que contraria a regra de nunca editar uma migration publicada. Foi aceitável porque não havia banco de produção com dados; a partir daqui a regra vale sem exceção. Os testes continuam em H2 (modo PostgreSQL).
- **Esforço:** Médio (8 arquivos).
- **Testes necessários:** Suíte completa em H2 no modo PostgreSQL. Testes contra um PostgreSQL real continuam pendentes (ver `docs/CONTEXTO.md`, seção "O que falta").
